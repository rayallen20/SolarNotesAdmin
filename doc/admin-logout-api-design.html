退出登录 API 对接定义

管理员确认退出后，服务端撤销当前会话的访问令牌。即使其他标签页仍持有同一枚令牌，后续请求也无法通过鉴权。

建议新增　POST /v1/admin/logout

目前后台顶栏的退出按钮会清理本地会话并返回登录页。后端已提供登录和修改密码接口，路由表中尚无退出接口。以下为待实现的对接约定。前端退出入口 · 后端路由表

1. 请求定义

请求体为空（0 字节）。 调用方只需在 Authorization 头中携带当前登录的 Bearer 令牌。路径参数、查询参数和 JSON 字段均为空，客户端可省略 Content-Type。后端从鉴权上下文取得管理员 ID 和本次令牌摘要，无需绑定 JSON。

HTTP直接请求后端 · 用测试管理员的令牌替换占位符
POST /v1/admin/logout HTTP/1.1
Host: 127.0.0.1:4060
Authorization: Bearer <access_token>
Content-Length: 0

通过现有开发代理联调时，浏览器看到的路径为 /api/v1/admin/logout。前端请求模块调用 request.post('/v1/admin/logout') 即可，公共请求实例负责加前缀和鉴权头。Vite 代理 · 公共请求实例

Shell通过 Vite 代理发起请求 · TEST_ACCESS_TOKEN 为测试令牌
curl --include --request POST \
  --header "Authorization: Bearer ${TEST_ACCESS_TOKEN}" \
  http://127.0.0.1:5062/api/v1/admin/logout

2. 响应定义

沿用管理端响应封装。服务端以 HTTP 200 返回 JSON，由数值型 code 表达业务结果，message 为字符串。退出接口在各业务分支的 data 均为空对象 {}。鉴权中间件已设置 Cache-Control: no-store。

JSON当前令牌已撤销
{
  "code": 200,
  "message": "success",
  "data": {}
}
JSON令牌缺失、无效、已撤销或已被新登录替换
{
  "code": 20004,
  "message": "登录状态无效,请重新登录",
  "data": {}
}
JSON令牌已过期
{
  "code": 20003,
  "message": "登录已过期,请重新登录",
  "data": {}
}
业务码含义接口约定
200当前会话已退出。撤销提交成功后返回。
20003JWT 已过期。复用公共鉴权响应；这枚令牌已不能访问受保护资源。
20004缺失或无效的令牌，或会话已撤销、替换，或账号记录已消失。包括使用仍在 JWT 有效期内的同一枚令牌再次退出。
10201数据库读取、写入或事务提交报错。复用数据库错误消息「数据库操作失败,请稍后重试」。
500服务内部错误，例如库中的非空令牌摘要格式损坏。复用内部错误消息「服务暂时不可用,请稍后重试」。

以上复用现有业务码。全局请求体中间件仍可因请求体超限或读取失败返回 10101；正常的零字节请求可直接通过。响应结构与业务码 · 全局请求体限制

3. 服务端撤销规则

现有登录逻辑在 admin.token_hash 中保存当前有效令牌的摘要。一次新登录可能在旧退出请求到达后、真正写库前发生。撤销操作必须核对发起退出的那枚令牌，以免旧请求清除后来建立的会话。

  1. 将路由注册在现有管理端鉴权下。通过 CurrentAdminID(c) 和 CurrentAdminTokenDigest(c) 取得管理员 ID 和已验证的令牌摘要。
  2. 参照改密流程，在事务中按管理员 ID 锁定记录。记录缺失、摘要已清空或与本次请求不匹配时，结束事务并返回 20004。可复用 auth.MatchSHA256Digest，兼容库中的大小写十六进制摘要；遇到损坏的非空摘要返回业务码 500。
  3. 匹配时仅将 token_hash 更新为空字符串并提交。用户名和密码摘要保持原值。提交后，用这枚令牌再次请求受保护资源会被拒绝。

例如，会话 A 发出退出请求后，会话 B 登录并先写入自己的摘要。等 A 获得行锁，摘要已变为 B，A 应收到 20004，B 仍可正常操作。两次并发退出同一有效会话时，一次成功，另一次发现令牌已失效；两次调用的最终状态一致。鉴权上下文 · 摘要比较 · 登录写入与改密锁行示例

4. 退出按钮如何处理结果

只有用户确认顶栏的「退出登录」才发起本请求。确认后记录发起请求时的令牌，再调用退出接口；请求进行中锁定确认按钮。若先清空 Pinia，现有请求拦截器会移除 Authorization 头。

收到的结果建议的前端操作
业务成功 200确认当前页面仍是发起请求的会话后，调用 userStore.clearSession()，再 router.replace({name: 'login'})。
鉴权已失效 20003 / 20004现有公共拦截器会核对请求令牌、清理相应会话并跳转。退出按钮的处理函数在此结束，避免重复提示或跳转。
服务端故障、超时或断网建议保留用户主动退出本机的意图：若仍为原会话，清理本机凭据并返回登录页，仅提示「本机已退出，未能确认服务器会话是否已撤销」。
请求期间本页已登录为新会话忽略旧请求的界面反馈和跳转；跨标签页时沿用 Store 中的令牌比对，保留其他标签页写入的新凭据。

修改密码成功时，后端已经撤销旧令牌。这里直接复用本地 clearSession() 即可。该 Store 方法也供公共鉴权错误处理调用，退出 API 的调用应放在顶栏的主动退出流程里。会话清理与跨标签页保护 · 公共鉴权失败处理 · 改密成功处理

5. 联调验收

以下为后端实现后的验收用例。用测试管理员登录取得尚未过期的令牌 A，先用 A 请求 GET /v1/planet/list 确认业务码为 200。

操作预期结果
点击退出确认框的「取消」。Network 中没有退出请求，A 仍可访问后台。
携带 A，以空请求体确认退出。返回成功示例中的 JSON。页面回到登录页，本机的令牌和用户名被清理。
仍在 JWT 有效期内，携带 A 再请求天体列表，再请求一次退出。两次均返回 20004。使用原账号密码重新登录后，新令牌可正常访问天体列表。
分别省略 Authorization 头、携带无效令牌、携带已过期的有效签名令牌。依次得到 20004、20004、20003；服务端未撤销其他会话。
并发用例：让 A 的退出请求通过鉴权后暂停，在同一账号的新登录 B 提交后恢复 A 的退出。A 得到 20004。B 随后请求天体列表仍返回 200。
在测试环境中模拟退出请求断网或响应丢失。按第 4 节约定，本机返回登录页，并告知服务端撤销结果尚未确认。

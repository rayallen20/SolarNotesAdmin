打开天体管理原型

天体管理 API 设计

现有后端支持列出、创建天体及逐项检查创建状态。为已确认的原型，建议新增一个编辑接口，并在状态接口中补充服务端的完整性检测结论。

接口变更一览

后端路由核对结果服务于页面的哪一步
GET /v1/planet/list现有 · 复用读取已创建记录。编辑抽屉从行数据回填。
GET /v1/planet/status现有 · 扩展响应保留九项创建状态，新增 data.readiness，供首次进入、重试和创建后复检。
POST /v1/planet/create现有 · 复用补建缺少的天体，成功后重新读取列表和状态。
POST /v1/planet/update建议新增按 ID 保存标题和简介，返回该条记录供列表回显。

这四个接口均使用管理端鉴权，携带 Authorization: Bearer <access_token>。POST 使用 Content-Type: application/json。下文展示完整 HTTP 响应体示例。现有控制器按项目约定用 HTTP 200 承载业务响应，数值型 code 表示业务结果。成功时 Axios 拦截器已解包到 data。

进入页面与复检

GET /v1/planet/status · 扩展响应

无请求体，无查询参数。现有 biz.Planet.ShowStatus() 对固定九个名称批量查库，按固定顺序返回 data.planets[].name 和 exist。已有数据足以在前端推算缺项。按本次由后端负责检测的要求，建议服务端直接汇总这批结果，在同一响应中给出结论，省去独立检测路由与重复查询。

建议新增字段类型与规则
data.readiness.ready布尔值。缺失清单为空时为 true。
data.readiness.required_count整数。固定集合的大小，当前为 9。
data.readiness.created_count整数。固定集合中 exist 为 true 的数量。
data.readiness.missing_names字符串数组。按固定顺序列出 exist 为 false 的精确名称，齐全时为 []。页面用 getBodyLabel() 转成中文。

缺少天体是检测成功得到的业务结果，仍返回 code: 200。页面在 ready === false 时显示「尚有未被创建的天体，前台页面无法正常启动」，并列出缺失名称。在 ready === true 时显示「太阳与八颗行星均已创建」。此检测范围是九个必需天体的创建状态。

汇总时逐项精确匹配大小写，沿用现有 names 的顺序。库中有历史额外名称时仍只核对这九项。空库应成功返回九项 exist: false、计数 0/9 和全部九个名称。查询失败时走错误响应，页面显示「暂时无法确认天体是否齐全」及「重试检测」。

兼容发布时可先上线后端扩展。现有 getBodyStatus() 校验并返回九项状态，旧调用方可继续使用。新页面在请求层解析同一响应的 planets 和 readiness，一次请求同时更新创建选项和检测卡。摘要缺失、类型错误或与明细不一致时按检测失败处理。

保存天体编辑

POST /v1/planet/update · 建议新增

按列表中的 planet.id 定位记录。为避免两位管理员互相覆盖，建议沿用已实现的书籍编辑契约：expected 是打开抽屉时记录的原文，target 是本次保存的完整标题与简介。两组均必填，即使只改一个字段也提交另一字段的值。

建议请求体 · 编辑太阳
{
  "planet": {
    "id": "2123435429930733568",
    "expected": {
      "title": "太阳系的中心",
      "intro": "太阳是太阳系中唯一的恒星。"
    },
    "target": {
      "title": "认识太阳",
      "intro": "太阳是太阳系中唯一的恒星，为地球提供光和热。"
    }
  }
}
建议成功响应 · 与列表中的单行同形
{
  "code": 200,
  "message": "success",
  "data": {
    "planet": {
      "id": "2123435429930733568",
      "name": "Sun",
      "title": "认识太阳",
      "intro": "太阳是太阳系中唯一的恒星，为地球提供光和热。"
    }
  }
}

ID 使用正 int64 范围内的十进制字符串，前端原样传递。expected.title 和 expected.intro 须为字符串，按读取时原文比较，包含首尾空白；允许历史空串。target 的两个字符串由后端去除首尾空白，再按 Unicode 码点校验，标题 1–20，简介 1–150。

写入字段白名单为 title、intro。id 仅定位，name 由服务器从已有记录回传，以保持前台资源匹配和书籍关联。列表中的历史名称也能按 ID 编辑。

建议在一个事务中按 ID 锁定记录，比对原文再更新。记录已不存在时返回 20102，原值变化时返回建议的新码 20103，两种情况均不写入。原值匹配且目标值相同时直接成功返回该行。事务提交后返回最终行，前端按 ID 替换列表对应项。修改标题和简介不影响天体创建状态，无须触发复检。

失败与恢复

建议失败响应 · 原文已变更
{
  "code": 20103,
  "message": "天体标题或简介已变化,请刷新后重新确认",
  "data": {}
}
业务码来源与含义页面处理
20003 / 20004现有 · 令牌过期或无效沿用公共鉴权拦截器处理。
10101现有 · 请求校验失败保留抽屉输入，提示检查字段。
20101现有 · 创建时名称已存在刷新列表和可创建选项。
20102现有 · 所选天体不存在建议让编辑接口复用此码。关闭失效记录的编辑抽屉，刷新列表及状态。
20103建议新增 · 天体编辑快照失效保留草稿，重读列表，管理员核对最新原文后再提交。
10201 / 500现有 · 数据库或服务内部错误检测失败可单独重试。编辑失败保留草稿；写请求超时时先重读记录核对结果。

现有 20102 在后端名为 BookPlanetNotFoundCode，前端常量为 BOOK_PLANET_NOT_FOUND。若用于天体编辑，建议抽出通用的天体不存在常量，保留现有书籍接口的数值及行为。建议把 20103 纳入前后端共同的响应码定义。所有错误响应的 data 沿用空对象。

联调验收与源码

操作或数据预期结果
初次进入，天王星和海王星缺失并行请求 list 和 status。列表可编辑，检测卡显示 7/9、缺失名称及原型中的提示。
库中有 9 条记录，但其中一条是历史额外名称若固定集合仅命中 8 项，仍显示 8/9 和缺少的那一项。
连续补建两个缺失天体每次创建成功都复检，依次显示 8/9 和 9/9，齐全后禁用创建入口。
检测请求出错后重试检测卡先显示未知状态，列表可独立展示；重试仅请求 status，以最新一次结果更新检测卡。
取消、正常保存、用旧原值保存取消不发请求；正常保存只更新对应天体的两项内容；过期快照收到冲突响应并保留草稿。

现有路由和返回格式按本地 Go 源码核对。本次交付为接口设计，新增字段、编辑接口和 20103 均属待实现契约。

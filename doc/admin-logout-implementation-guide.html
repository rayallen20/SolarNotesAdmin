退出登录实现与 API 联调

管理员在顶栏确认退出后，前端先让服务端撤销当前令牌，再清理本地会话并返回登录页。

本指南基于已有的退出确认框。第 2 节扩展 src/api/admin.js，第 3 节修改 src/views/LayoutPage.vue。这两处改动可直接复用项目的 Axios 实例、Pinia Store 和登录路由。

1. 后端实现核对

已实现　POST /v1/admin/logout

路由受管理员鉴权保护。请求体为 0 字节。前端通过 Authorization: Bearer <access_token> 标识当前会话。后端的 admin.Logout 从上下文读取管理员 ID 和令牌摘要；RevokeSession 在事务中锁定管理员记录，重新核对摘要，只将匹配会话的 token_hash 清空，提交后返回成功。路由注册 · 控制器 · 业务错误映射 · 锁行与撤销

JSON成功时 Network 面板看到的完整响应
{
  "code": 200,
  "message": "success",
  "data": {}
}

成功和业务错误都使用 HTTP 200，data 均为空对象。20003 表示 JWT 已过期，20004 表示缺少有效令牌、令牌已撤销或已被新登录取代。数据库故障和内部异常分别使用 10201 和 500。前端按响应体的数值型 code 处理。鉴权中间件 · 响应封装

后端实测。 在独立 MySQL 和一次性管理员账号上，通过真实 Gin 路由验证了空请求体退出、旧令牌再次访问和重复退出。另一次测试让 A 在通过鉴权后暂停，待同账号的新登录 B 提交后再继续退出：A 收到 20004，B 仍能读取天体列表。

3.3 替换原有的 logout 函数

把文件中原来的 logout() 及其 JSDoc 替换为下面两个函数。logout() 控制按钮忙碌状态；logoutSession() 处理这次确认所对应的会话。必须在发送请求时保留 Pinia 令牌，提前执行 clearSession() 会让拦截器移除鉴权头。

替换函数src/views/LayoutPage.vue · 顶栏主动退出
/**
 * 处理顶栏的退出确认, 并阻止重复提交.
 * @returns {Promise<void>} 退出操作结束.
 */
async function logout() {
    if (logoutPending.value === true) {
        return
    }

    logoutPending.value = true
    try {
        await logoutSession(userStore.token)
    } finally {
        logoutPending.value = false
    }
}

/**
 * 撤销发起请求时的会话, 清理本地凭据并返回登录页.
 * @param {string} submittedToken 用户确认退出时的令牌.
 * @returns {Promise<void>} 请求和页面反馈均处理完成.
 */
async function logoutSession(submittedToken) {
    /** @type {boolean} 是否需要向用户说明服务端撤销结果尚未确认. */
    let revocationUnconfirmed = false

    if (submittedToken !== '') {
        try {
            await logoutAdmin()
        } catch (error) {
            if (isAuthError(error) === true) {
                // 公共拦截器已根据请求令牌处理相应会话.
                return
            }
            revocationUnconfirmed = true
        }
    }

    if (userStore.token !== submittedToken) {
        // 旧请求的结果不能清理本页后来建立的新会话.
        return
    }

    userStore.clearSession()
    if (revocationUnconfirmed === true) {
        ElMessage.warning('本机已退出, 未能确认服务器会话是否已撤销')
    }

    try {
        const failure = await router.replace({name: 'login'})
        if (isNavigationFailure(failure) === false || router.currentRoute.value.name === 'login') {
            return
        }
    } catch {
        // 导航异常和被阻止的导航共用下方提示.
    }
    if (userStore.token === '') {
        const loginPath = router.resolve({name: 'login'}).href
        ElMessage.error('未能打开登录页, 请手动访问 ' + loginPath)
    }
}

4. 会话清理与跳转

情况前端处理
服务端确认成功清理本标签页的 Pinia 会话及匹配的本地凭据，然后调用 router.replace({name: 'login'})。直接访问受保护路由时，路由守卫也会检查令牌。
业务码 20003 或 20004现有 unwrapResponse() 等待 handleAuthFailure() 核对请求头、处理匹配会话后再拒绝 Promise。按钮捕获到鉴权错误便结束，整次操作只提示和跳转一次。
数据库错误、服务内部错误、超时或断网尊重管理员主动退出本机的选择，清理相应的本地会话后仍前往登录页，并说明服务端撤销结果未确认。界面不会自动重发退出请求。
退出请求发出后重新登录同标签页用 submittedToken 快照检查回包是否仍属于当前会话。若另一个标签页已写入新令牌，现有 clearSession() 会保留新令牌和对应用户名。后端也会在行锁内比对摘要，旧请求只能撤销自己对应的会话。

将网络调用放在顶栏的 @confirm 流程中。公共鉴权错误和修改密码成功都会直接调用 clearSession()。改密成功时后端已撤销令牌，继续沿用现有的改密跳转即可。Store 的会话清理 · 鉴权错误分类 · 改密成功处理 · 路由守卫

异常与并发验收

测试操作预期结果
旧标签页保留 A，在另一标签页重新登录取得 B。先让旧标签页点击退出，再用 B 打开受保护页面。旧标签页收到 20004 并回登录页，B 的本地凭据和服务端会话仍有效。若 A 本身已经过期，公共处理接收 20003。
仅延迟 A 已发出的退出响应，再在同标签页建立 B 会话，最后放行 A 的响应。晚到的回包不会清除 B 或将 B 带回登录页。
断网后确认退出，或在测试代理中将响应延迟超过当前 Axios 的 5 秒超时。本机清理登录信息并转到 /login，提示服务器撤销结果未确认；Network 中仅有一次退出尝试。
用两份并发请求携带同一有效令牌 A 退出。一次业务成功，一次 20004。之后持 A 访问受保护接口会被拒绝。

打开目录管理交互原型

目录管理 API 设计

管理后端已实现本页使用的 6 个接口，涵盖按天体选书、读取目录树、保存排序、设置显隐和预览 Markdown。

目录由可见切为隐藏时，会同时隐藏全部后代。 手动关闭显隐开关或把可见目录移回待排区，都会触发这一规则。后代保留各自的序号。再次显示目录时，只显示该目录。

页面什么时候发请求

触发时机方法与管理 API 路径用途
进入目录管理GET /v1/planet/list列出已创建的天体。
选择或切换天体POST /v1/book/options列出该天体下所有可管理的书籍，包括隐藏书籍。
选中书籍POST /v1/catalogue/tree取得书籍当前状态和全部目录节点。
抽屉中点击「保存排序」POST /v1/catalogue/reorder保存该层的阅读顺序，在同一事务中处理节点显隐。
点击目录显隐开关POST /v1/catalogue/display设置节点的目标状态，由显示切为隐藏时同步隐藏全部后代。
点击可预览的 Markdown 文件POST /v1/article/preview获取图片 URL 已处理的 Markdown 正文。

默认只展开根节点。展开、折叠、选中目录、计算进度，以及抽屉中的加入、撤回、上移、下移和取消，均可基于本地目录数据完成。「还原示例」是原型工具，正式后台没有对应的写接口。

鉴权与响应格式

表中路径是管理后端注册的路径。开发环境由前端请求实例加上 /api 前缀，Vite 代理转发时将其去掉。所有 6 个接口都需要已登录管理员的 Bearer token，POST 的请求体为 JSON。

HTTP请求头 
Authorization: Bearer <access_token>
Content-Type: application/json

下文的响应示例均为完整 HTTP 响应体。沿用现有管理 API 约定，正常业务处理以及约定的业务失败均返回 HTTP 200，判断结果看数值型 code。成功时 message 为 "success"，前端 request 拦截器会解包 data。所有雪花 ID 在 JSON 中使用十进制字符串，前端原样传回。

③ 读取一本书的完整目录树

各层目录节点的字段类型与约定
id、parent_id字符串。根节点的 parent_id 固定为 "0"，其余节点的 parent_id 等于直接父节点的 id。例如编排第一章的子项时，排序请求的 parent_id 填第一章的 id。
children必返数组，只含当前节点的直接子项，各项沿用同一节点结构。文件和空文件夹都返回 []，由 type 区分。
name、type名称用于展示。type 决定点击行为：folder 用于浏览目录，即使为空也按文件夹处理；file 表示 Markdown 文章节点，点击后用该节点的 id 请求预览。
sort整数或 JSON null。根固定为 0，非根的已排序节点从 1 开始，同一书、同一父目录下唯一。null 表示待排序。
display_status节点实际保存的 visible 或 hidden。待排序节点只能是 hidden。隐藏可见目录时，后端将全部后代的该字段也写为 hidden。书籍自身的状态取自 book.display_status。

后端统一排列每组 children，已排序项按 sort 升序在前，待排序项按中文名称自然顺序在后（数字按数值比较），同名时按 ID 升序。前端将 data.book.catalogues 直接交给树组件，默认选中并只展开根节点；右侧列表直接展示选中目录的 children。

书籍状态取 data.book.display_status。全书进度可通过遍历整棵树计算，为「已排序的非根节点数 / 全部非根节点数」，独立于显隐及展开状态。

书籍存在、目录尚未导入时，data.book.catalogues 返回空数组 []，页面显示「目录尚未导入」，禁用编排。书籍不存在时返回业务失败。

④ 保存一个父目录下的阅读顺序

POST/v1/catalogue/reorder

抽屉打开时保留本层的已排顺序和待排成员，作为 expected。管理员可加入、移动或移回待排区，得到 target。点击「保存排序」时同时提交这两份分组。点击「取消」则丢弃草稿。

请求三章起初均待排, 先排入第三章和第一章 
{
  "catalogue": {
    "parent_id": "2123684178040987648",
    "expected": {
      "sorted_children": [],
      "unsorted_children": [
        {"id": "2123684178049376256"},
        {"id": "2123684178049376278"},
        {"id": "2123684178049376301"}
      ]
    },
    "target": {
      "sorted_children": [
        {"id": "2123684178049376301"},
        {"id": "2123684178049376256"}
      ],
      "unsorted_children": [
        {"id": "2123684178049376278"}
      ]
    }
  }
}
响应排序事务已提交 
{
  "code": 200,
  "message": "success",
  "data": {}
}

本例保存后，第三章为 1 / visible，第一章为 2 / visible，第二章为 null / hidden。成功后前端重取该书的目录树，按 ID 恢复当前目录和展开位置，再更新进度。后续示例展示如何同时保存两个方向的状态转换。查看第三章移回待排区的完整请求

三个必填字段

  • parent_id 指向待编排的文件夹。后端由父节点查出所属书籍，并核对其直接子节点的父 ID 和书籍归属。编排根目录下的章节时，传根节点本身的 ID。
  • expected 是打开抽屉时的快照。后端按当前 sort 比对 sorted_children 的 ID 序列，按 ID 集合比对 unsorted_children。仅改变待排区的展示次序或单独切换显隐，均不产生排序冲突。
  • target 是保存后的目标分组。sorted_children 的位置依次对应序号 1 至 N，unsorted_children 中的节点均为待排序。任一组均可为空，包括一次把所有节点移回待排区。

每份分组都必须提供上述两个数组，并完整列出该层全部直接子节点。每项仅引用一个节点，形如 {"id": "2123684178049376256"}。两份分组覆盖相同的 ID 集合，每份内的每个 ID 只能出现一次。只排一部分节点时，将其余节点列入待排组。

保存后的节点状态

保存时的分组目标分组最终序号最终显隐
待排已排目标位置仅当前节点设为 visible，首次加入和重新加入均适用。
已排待排null当前节点设为 hidden。原为 visible 时同步隐藏全部后代，原为 hidden 时仅清除当前节点的序号。
已排已排目标位置保留锁定记录中的最新显隐。
待排待排nullhidden。

序号的修改范围是当前编排层的直接子项。对最终由可见转为隐藏的目录，后端在同一事务中递归更新其同书后代的 display_status，即使遇到已隐藏的中间目录也继续向下处理。后代保留各自的 sort。取消草稿，或将已排节点移出再加回后保存，都不会因此隐藏其后代。

并发校验与原子写入

  1. 校验请求形状、ID 格式、分组内唯一性以及两份分组的成员集合。以 parent_id 查出书籍，事务内先锁定该书，再重新读取并锁定父目录和其直接子节点，核对归属。显隐接口与会改变目录的导入操作采用一致的加锁顺序。
  2. 先把锁定后的实际分组与 expected 比较。成员变化、某节点换组、已排序列变化，均返回 20302 并放弃整批写入。校验通过后才可应用 target。
  3. 记下锁定记录的原分组，先释放被移动的已排序号（事务内临时写 SQL NULL），再按目标位置分配 1..N。这可避免交换两项时与唯一索引 uk_book_parent_sort(book_id, parent_id, sort) 冲突。按上表更新显隐并提交，任一步失败则回滚。
  4. 遇到冲突或响应丢失，前端重读该书目录树以同步显隐，再核对本层分组。若最新的已排序列与待排集合已符合 target，可结束此次操作。若仍有差异，请管理员基于最新分组确认，再次保存时使用新的 expected。

排序示例：第三章移回待排区，第二章加入阅读顺序

假设第三章排第 1 且可见，第一章排第 2 且已被管理员手动隐藏，第二章待排。管理员现在打开「编排本级」，移出第三章并加入第二章，点击「保存排序」时发送以下请求。

请求第三章移回待排区, 第二章加入阅读顺序 
{
  "catalogue": {
    "parent_id": "2123684178040987648",
    "expected": {
      "sorted_children": [
        {"id": "2123684178049376301"},
        {"id": "2123684178049376256"}
      ],
      "unsorted_children": [
        {"id": "2123684178049376278"}
      ]
    },
    "target": {
      "sorted_children": [
        {"id": "2123684178049376256"},
        {"id": "2123684178049376278"}
      ],
      "unsorted_children": [
        {"id": "2123684178049376301"}
      ]
    }
  }
}

成功响应仍为 data: {}。第一章继续保留手动隐藏，序号变为 1。第二章加入阅读顺序，变为 2 / visible。第三章移回待排区，变为 null / hidden。若该章有后代，后代全部隐藏并保留原序号。本层已排序总数仍是 2。

⑤ 单独设置一个节点的显示状态

POST/v1/catalogue/display

请求只需节点 ID 和目标显示状态。catalogue.id 是目录表的主键，后端可由节点记录取得所属书籍。下例把当前可见的第一章隐藏。第一章和该章下各级目录、文件随即全部隐藏，第一章的序号仍为 2。

请求隐藏已经排序的第 1 章 
{
  "catalogue": {
    "id": "2123684178049376256",
    "display_status": "hidden"
  }
}
响应状态设置成功 
{
  "code": 200,
  "message": "success",
  "data": {}
}
  • 按 catalogue.id 查找目标节点，节点不存在时返回 20301。display_status 只接受 visible 或 hidden。
  • 沿用排序接口的加锁顺序。根据节点记录中的 book_id 先锁定所属书籍，再锁定节点并复核归属。若目标为 visible，用锁定后的 sort 校验：非根节点尚未排序时返回 20303，根节点的序号 0 有效。
  • 锁定记录原为 visible、目标为 hidden 时，同一事务会隐藏当前节点和它在本书内的全部后代。隐藏根节点会覆盖整本书的目录树。所有节点保留各自的序号，书籍自身的显隐也保留。
  • 切换为 visible 时只显示当前节点。原状态已经等于目标时直接成功，重复请求隐藏不会再次级联。两人设置不同的合法目标时，以最后提交的事务为准。
  • 业务码 code === 200 表示本次写入已成功。隐藏成功时响应的 data 是空对象，实际切换与重复提交返回相同结果。前端调用 POST /v1/catalogue/tree 重读该书目录树，刷新子树开关。显示成功时可直接更新当前节点的开关。若写请求超时或响应丢失，也先读取最新状态，再决定是否重试。

正文由 API 读取，图片由 Nginx 提供

  1. 验证管理员身份，按目录 ID 核实节点类型为 file，再查询关联的文章记录。若记录缺失或 Markdown 文件已不存在，返回 ARTICLE_PREVIEW_UNAVAILABLE。按 storage.root_dir 解析 article.path。目前抽查到的记录包含 /solar-notes-data/ 绝对前缀，表注释约定为根相对路径，两类记录都应解析到同一存储根内。
  2. 解析正文中的 Markdown 图片目标。例如 ![查询请求执行过程](./img/查询请求执行过程.jpg) 以当前 .md 所在目录为起点。规范化实际文件路径并检查根目录边界（含符号链接），从根取相对路径，逐段做 URL 编码后拼到 asset.base_url。已有 HTTP(S) 图片 URL 和代码块中的示例文本原样保留。仅替换返回的正文。
  3. 本地开发配置的资源基址为 http://192.168.1.60:8080。浏览器渲染前净化转换后的 HTML，可参考阅读端使用的 marked 和 DOMPurify。虚拟机 Nginx 继续提供图片并拒绝直接访问 .md；管理鉴权仍由预览 API 执行。

错误响应与页面恢复

下表列出管理后端 resp_body 已定义的业务码。前端接入时在 API_CODE 中统一引用这些数值，按 code 处理响应，并向管理员展示 message。

失败响应当前分组与打开抽屉时的快照不一致 
{
  "code": 20302,
  "message": "目录状态已变化, 请刷新后确认排序",
  "data": {}
}
业务码条件页面处理
20003 / 20004令牌过期 / 缺失、无效或已撤销。交给公共鉴权拦截器清理会话并返回登录。
10101字段缺失、ID 类型错误、非法枚举、分组内或两组间重复 ID、目标成员与快照成员集合不同，或将父节点列为子项。保留输入并说明原因，整批排序不生效。
20102书籍选项请求引用的天体已不存在，沿用项目现有天体引用错误。刷新天体选择，清空下游选项。
20202 · BOOK_NOT_FOUND选中的书籍已不存在。重取当前天体的书籍选项。
20301 · CATALOGUE_NOT_FOUND目标目录或文件节点已被删除。重取树，定位到仍存在的父节点或根。
20302 · CATALOGUE_ORDER_CHANGED父目录存在，但其直接子节点的当前已排序列或待排集合与 expected 不一致。重读树，核对最新分组后再决定是否提交。
20303 · CATALOGUE_SORT_REQUIRED请求显示未排序的节点。提示先排序，并刷新节点状态。
20401 · ARTICLE_PREVIEW_UNAVAILABLE节点存在，但类型不支持、缺文章记录或 Markdown 文件已不存在。提示文章暂时无法预览。
10201 / 500数据库错误 / 内部错误，包括存储配置或读文件异常。写请求结果不明时先重读树；预览错误不展示磁盘绝对路径。

操作应该观察到的结果
选无书天体，再切回有书天体空选项和旧目录正确清除。隐藏书可选择，书籍状态只读。
首次选书，展开第一章，再取消编排初始只展开根。展开和取消都不发写请求，进度不变。
先排第三章、第一章，手动隐藏第一章，再移出第三章并加入第二章第一章及其后代保持隐藏。第三章清除序号并与后代一起隐藏，后代序号保留。第二章获得序号并显示。
把全部已排节点移回待排区，先取消，再重复操作并保存取消时树中各层均保留原状。保存后本层直接子项均为 null / hidden，原先可见的子项会级联隐藏后代。重新加入其中一项时只显示该项。
尝试显示待排节点，再将可见的根节点隐藏并重新显示待排节点返回 20303。隐藏根时整棵树均隐藏，再显示根时只有根恢复显示。根序号始终为 0，后代序号及书籍自身的状态保留。
在可见章节下准备一个已隐藏的子目录和其中的可见文件，再隐藏该章节文件随章节一同隐藏，即使中间目录原来已隐藏。文件序号及同级其他章节的状态保留。
隐藏一个已排目录后，单独显示其中的已排文件，再重复提交隐藏该目录，随后将该目录移回待排重复隐藏是幂等操作，已隐藏目录移回待排仅清除自身序号。两步操作均保留已单独显示的文件及其序号。
甲、乙用相同快照提交不同目标，甲先保存并改变顺序或分组乙收到 20302，甲的结果保留。若甲仅改了显隐，乙仍可保存，持续已排节点保留其最新显隐。
同一 ID 同时列入目标的已排和待排两组，或目标比快照少列一个 ID返回 10101。将已排项明确移入待排组是合法操作，遗漏该 ID 会触发校验错误。
预览含相对图片的隐藏 Markdown，再点击普通目录或图片节点前者能显示正文和图片；后者按节点类型导航，不请求文章正文。失效令牌无法读取管理预览。

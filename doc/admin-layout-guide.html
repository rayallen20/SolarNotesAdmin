3. 创建后台布局页

使用现有 Element Plus 组件和图标库。菜单通过路由名称解析完整路径，绑定到 :index，避免在菜单中重复填写路径。通过 :default-active="activeMenuPath" 匹配按当前路由名称解析出的路径，确保刷新页面或访问带结尾斜杠的地址时仍能高亮当前菜单。

<script setup>
import { computed } from 'vue'
import { useRoute, useRouter } from 'vue-router'
import { Document, HomeFilled, Sunny, SwitchButton, User } from '@element-plus/icons-vue'
import useUserStore from '@/stores/user'

defineOptions({
    name: 'LayoutPage',
})

/**
 * 当前路由信息，供菜单高亮和页面标题使用。
 * @type {import('vue-router').RouteLocationNormalizedLoaded}
 */
const route = useRoute()

/**
 * 路由实例，用于解析菜单路径和退出后返回登录页。
 * @type {import('vue-router').Router}
 */
const router = useRouter()

/**
 * 根据路由名称获取菜单对应的完整路径。
 * @param {string} routeName 路由配置中唯一的名称。
 * @returns {string} 根据当前路由配置解析出的完整路径。
 * @throws {Error} 路由名称不存在或缺少必填路径参数时抛出。
 */
function getMenuPath(routeName) {
    return router.resolve({ name: routeName }).path
}

/**
 * 当前选中菜单的规范路径，与菜单项 index 使用相同的解析规则。
 * @type {import('vue').ComputedRef<string>}
 */
const activeMenuPath = computed(getActiveMenuPath)

/**
 * 根据当前路由名称计算应高亮的菜单路径。
 * @returns {string} 当前路由的规范路径；没有字符串路由名称时返回空字符串。
 */
function getActiveMenuPath() {
    if (typeof route.name === 'string') {
        return getMenuPath(route.name)
    }

    return ''
}

/** 与登录页共享的用户 Store 实例。 */
const userStore = /** @type {import('@/stores/user').UserStore} */ (useUserStore())

/**
 * 当前页面的标题。
 * @type {import('vue').ComputedRef<string>}
 */
const pageTitle = computed(getPageTitle)

/**
 * 获取当前路由配置的标题。
 * @returns {string} 当前页面标题或默认标题。
 */
function getPageTitle() {
    if (typeof route.meta.title === 'string') {
        return route.meta.title
    }

    return '管理后台'
}

/**
 * 当前用户名；尚未接入登录时，显示预览身份。
 * @type {import('vue').ComputedRef<string>}
 */
const username = computed(getUsername)

/**
 * 获取当前用户名，空字符串时使用预览身份。
 * @returns {string} 当前用户名或预览身份名称。
 */
function getUsername() {
    if (userStore.username !== '') {
        return userStore.username
    }

    return '预览用户'
}

/**
 * 清空本地用户会话，并返回登录页。
 * 后续若有服务端退出接口，在这里接入对应调用。
 * @returns {Promise<void>}
 */
async function logout() {
    userStore.clearSession()
    await router.replace({ name: 'login' })
}
</script>

路径变化时，菜单如何跟随更新

getMenuPath('userList') 使用 router.resolve({ name: 'userList' }).path 从路由配置解析完整路径。它只计算目标地址，不执行跳转；点击菜单时， el-menu 的 router 模式会使用解析出的 index 进行跳转。

路由配置修改前修改后
父路由 path/admin/manage
用户页子路由 pathusersmembers
用户页路由 nameuserListuserList
自动生成的菜单 index/admin/users/manage/members

只要路由的 name 保持不变，修改父路径或子路径后，菜单模板就可以继续使用 :index="getMenuPath('userList')"。当前三个菜单对应的名称分别是 dashboard、userList 和 noteList；名称须与路由配置对应且保持唯一。 高亮值 activeMenuPath 也按当前路由的 name 解析， 与菜单项的 index 使用同一规则，避免 /admin/users/ 与 /admin/users 的字符串差异导致菜单未选中。

原因分析、分步修改和验证地址见：菜单高亮修复文档。

参考：Vue Router 命名路由、router.resolve()。

样式限定在布局组件内部，固定整体视口高度，由右下内容区独立滚动。min-width: 0 避免内容把右侧区域撑出屏幕；窄屏时保留图标、隐藏菜单文字。

这里位于组件的 setup 上下文中，可以调用 useUserStore()。用户名通过 userStore.username !== '' 明确判断；同一个 Pinia 实例内会与登录页共享用户状态。

参考：Element Plus 菜单、Pinia Store 的使用上下文。

5. 配置嵌套路由

沿用先定义路由列表、再定义 option、创建 router、最后默认导出的写法。子路由的 path 不以 / 开头，由父路径 /admin 拼出完整地址。

src/router/index.js · 完整示例
import { createRouter, createWebHistory } from 'vue-router'

/**
 * 路由列表：登录页独立，后台布局下挂载三个子路由。
 * @type {import('vue-router').RouteRecordRaw[]}
 */
const routes = [
    {
        path: '/',
        redirect: '/login',
    },
    {
        path: '/login',
        name: 'login',
        component: () => import('@/views/LoginPage.vue'),
    },
    {
        path: '/admin',
        component: () => import('@/views/LayoutPage.vue'),
        redirect: { name: 'dashboard' },
        children: [
            {
                path: 'dashboard',
                name: 'dashboard',
                component: () => import('@/views/PlaceholderPage.vue'),
                meta: {
                    title: '工作台',
                    description: '查看后台概况与常用功能。',
                },
            },
            {
                path: 'users',
                name: 'userList',
                component: () => import('@/views/PlaceholderPage.vue'),
                meta: {
                    title: '用户管理',
                    description: '查看和管理用户信息。',
                },
            },
            {
                path: 'notes',
                name: 'noteList',
                component: () => import('@/views/PlaceholderPage.vue'),
                meta: {
                    title: '笔记管理',
                    description: '查看和管理笔记内容。',
                },
            },
        ],
    },
]

/**
 * 路由配置。
 * @type {import('vue-router').RouterOptions}
 */
const option = {
    routes,
    history: createWebHistory(import.meta.env.BASE_URL),
}

/**
 * 应用共用的路由实例。
 * @type {import('vue-router').Router}
 */
const router = createRouter(option)

export default router

7. 后续衔接登录与退出

实际登录 API 接入后，继续复用现有 setSession(token, username)，保存会话后再跳转到工作台。下面是对现有 LoginPage.vue 的增补参考，保留原有 userStore 定义，替换原来的同名回调：

src/views/LoginPage.vue · script setup 增补参考
import { useRouter } from 'vue-router'

/**
 * 登录页使用的路由实例。
 * @type {import('vue-router').Router}
 */
const router = useRouter()

/**
 * 保存登录接口返回的会话信息，并进入后台工作台。
 * @param {string} token 服务端发放的非空 Token。
 * @param {string} username 非空用户名。
 * @returns {Promise<void>}
 * @throws {TypeError} 会话参数不是非空字符串时抛出。
 */
async function onLoginSuccess(token, username) {
    userStore.setSession(token, username)
    await router.replace({ name: 'dashboard' })
}

布局页中的 logout() 已展示退出步骤：确认后调用 userStore.clearSession()，再通过 router.replace({ name: 'login' }) 返回登录页。

页面框架确定后，再根据实际登录接口补充路由守卫和会话有效性校验。当前的预览方案保留直接访问后台路径的能力，清空本地会话不会禁止手动重新打开这些占位页。

8. 实现后检查这些行为

  1. 打开 /login，登录页独立显示；打开 /admin，显示后台框架并跳转到工作台。
  2. 点击三个菜单，地址、菜单高亮、顶部标题和内容区同步更新；左侧菜单栏与顶部用户栏保持显示。
  3. 刷新 /admin/users，仍显示用户管理并高亮对应菜单。
  4. 直接打开或刷新 /admin/users/，也应高亮用户管理；结尾斜杠不应影响选中状态。
  5. 保持路由 name 不变，修改父路由或子路由的 path，菜单应自动使用新地址，跳转和高亮均正常。
  6. 没有用户会话时显示“预览用户”；登录成功保存会话后显示实际用户名。
  7. 点击退出并选择取消，保留当前页面；选择确认，清空会话并返回登录页。
  8. 缩小窗口，左侧保留可点击的图标导航；右侧内容不撑破页面。

打开书籍管理交互原型

书籍管理 API 设计

新版书籍管理页需要 5 个管理接口。天体列表和书单可以直接复用，创建接口需要支持自动分配末位序号，编辑书籍和保存书序需要新增路由。

页面动作与后端接口

页面动作方法与路径当前后端
进入书籍管理页GET /v1/planet/list直接复用，提供已创建的天体。
选择天体或刷新列表POST /v1/book/options直接复用，返回该天体的完整书单，包含隐藏书籍。
确认添加POST /v1/book/create改造现有接口，排序值由后端在创建时分配。
编辑后保存POST /v1/book/update建议新增，一次保存标题和书籍自身的显隐。
保存书序POST /v1/book/reorder建议新增，一次提交当前天体下所有书籍的目标顺序。

打开抽屉、统计显隐数量、上下移动、取消修改都在本地完成。编辑抽屉用选中行回填，「还原示例」只操作原型数据。书籍 ID 保存在行数据中，用于编辑、调序和识别同名书。

现有 POST /v1/book/list 按全库分页，入参只有 pagination。原型要求同一天体的完整书单才能统计和调序，直接调用 book/options 即可。目录管理的 catalogue/display 和 catalogue/reorder 写入目录节点，书籍写操作由本页的 book 接口处理。

请求与响应约定

下列路径均为后端注册路径。前端开发环境的 Axios 实例加上 /api 前缀，Vite 代理转发时去掉该前缀。所有接口都要求管理员登录，POST 使用 JSON。天体和书籍 ID 在 JSON 中始终为正 int64 的十进制字符串，前端原样保存和提交。

HTTP管理 API 请求头 
Authorization: Bearer <access_token>
Content-Type: application/json

示例给出完整响应体。后端按项目惯例用 HTTP 200 返回已处理的业务结果，以数值型 code 判断成功或失败。成功时前端的 request 拦截器返回 data，失败时保留错误对象。下文标明「现有」的内容来自后端源码，标明「建议」的内容是待实现的契约。示例 ID 和书名用于说明字段之间的对应关系。

直接复用的两个读接口

POST /v1/book/options

选择天体后调用已有的 getBookOptions(planetId)。后端按 planet_id 读取可见和隐藏书籍，先按 sort、再按 id 升序返回全部行。列表只展示排序值、标题、显隐和操作。总数取 books.length，显示数与隐藏数按 display_status 统计。

改造现有接口 POST /v1/book/create

当前实现要求 book.sort 为必填正整数（Go 类型为 uint32），按客户端传入的值写库，成功返回 data: {}。把表单改成只读并继续提交前端算出的值，只能覆盖书单没有跳号、也没有其他管理员同时写入的情况。

建议契约

新客户端提交已选天体、书名和初始显隐。书名去除首尾空白后为 1 至 20 个 Unicode 码点，display_status 只取 visible 或 hidden，原型默认选中「显示」。成功响应沿用现有结构。

建议请求在所选天体下追加一本书 
{
  "book": {
    "planet": { "id": "2123435429930733568" },
    "title": "数据库索引设计",
    "display_status": "visible"
  }
}
成功响应事务提交后返回 
{
  "code": 200,
  "message": "success",
  "data": {}
}

打开添加抽屉时，页面用当前书单长度加 1 显示只读序号。后端以提交时该天体的全部书籍数为准分配 N + 1。已有 5 本就分配 6，首本分配 1，隐藏书籍也占一个位置。创建成功后重新调用 book/options，显示实际分配的序号；上面的两本书示例会新增第 3 本。

新旧客户端如何切换

目前 src/api/book.js 的 addBook(form) 发送 book.sort。建议先发布兼容的新后端，再发布省略该字段的新前端。过渡期间，旧客户端传来的正整数只用于核对期望末位，恰好等于事务分配值时接受，其他值返回 10101 并提示刷新书单。新版后端的所有调用方都按末尾追加；旧版后端收到省略 sort 的请求会返回 10101。

历史数据与并发追加

旧接口允许跳号，现有书籍选项读取逻辑也兼容历史序号 0。切换写入规则前，按天体检查实际序号，依原有 (sort, id) 顺序将有缺口或从 0 起排的书单整理为 1..N，迁移时与旧写入协调。假设现有序号为 1、3，整理为 1、2 后追加的新书才会正确得到 3。

创建与调序都在事务中先锁同一条天体记录，再读取当前书单。即使天体下还没有书也能锁定。现有创建只对天体加共享锁，改造后两种写操作须共用排他锁并保留 (planet_id, sort) 唯一约束。两人同时向有 5 本书的天体追加时，成功的两笔写入应依次得到 6、7。

建议新增 POST /v1/book/update

点击行内「编辑」后，抽屉只允许修改标题和书籍显隐。保存时用 book.id 定位单本书，expected 带上打开抽屉时的两个原值，target 带上保存后的两个值。两个对象都需要标题和显隐字段，改其中一项时，另一项沿用表单原值。目标字段的校验规则与创建相同。

建议请求给刚添加的书改名并隐藏 
{
  "book": {
    "id": "5000000000000000001",
    "expected": {
      "title": "数据库索引设计",
      "display_status": "visible"
    },
    "target": {
      "title": "数据库索引设计笔记",
      "display_status": "hidden"
    }
  }
}
建议响应返回已保存的书籍摘要 
{
  "code": 200,
  "message": "success",
  "data": {
    "book": {
      "id": "5000000000000000001",
      "title": "数据库索引设计笔记",
      "sort": 3,
      "display_status": "hidden"
    }
  }
}

后端在事务中按 book.id 执行 SELECT ... FOR UPDATE 锁定该书，再将当前标题和显隐与 expected 逐字段精确比较。快照中的书名保留读取时的原文，去首尾空白和长度校验用于目标书名。核对通过后只更新标题和显隐。书籍已删除时返回 20202，原值已变化时建议返回 20204。仅调整过书序时仍可保存编辑，书内目录各自的状态随原记录保留。

成功响应中的书籍字段与 book/options 的单项相同。前端可以按字符串 ID 更新该行及显隐统计。如果响应中的序号与本地原值不同，说明其间发生了调序，应刷新该天体的完整书单。

建议新增 POST /v1/book/reorder

进入「调整书序」时复制当前天体的全部书籍 ID 作为 expected.books，移动行只修改草稿。点击「保存书序」时，把最终序列放入 target.books。每项只传 id，数组位置从 1 开始对应新排序值。隐藏书籍也必须出现一次。

建议请求把刚编辑的书移到第 2 位 
{
  "planet": {
    "id": "2123435429930733568",
    "expected": {
      "books": [
        { "id": "2123435620763176960" },
        { "id": "4100000000000000002" },
        { "id": "5000000000000000001" }
      ]
    },
    "target": {
      "books": [
        { "id": "2123435620763176960" },
        { "id": "5000000000000000001" },
        { "id": "4100000000000000002" }
      ]
    }
  }
}
建议响应返回保存后的整份书单 
{
  "code": 200,
  "message": "success",
  "data": {
    "books": [
      {
        "id": "2123435620763176960",
        "title": "MySQL是怎样运行的",
        "sort": 1,
        "display_status": "visible"
      },
      {
        "id": "5000000000000000001",
        "title": "数据库索引设计笔记",
        "sort": 2,
        "display_status": "hidden"
      },
      {
        "id": "4100000000000000002",
        "title": "SQL 学习笔记",
        "sort": 3,
        "display_status": "hidden"
      }
    ]
  }
}
  1. 校验输入。 两个数组必填，元素必须是合法 ID 引用，各自没有重复，且两个数组是同一组书籍的排列。目标遗漏、额外添加或者重复任何一本均返回 10101。
  2. 校验当前书单。 在事务中先锁定天体，再按 sort, id 使用 FOR UPDATE 读取并锁定该天体的书籍行。天体不存在返回 20102。当前 ID 序列与 expected.books 的长度或任一位置不一致时返回 20203，整次写入回滚。即使两份数组都含有外天体 ID，也通不过这一步。
  3. 一次提交新顺序。 只按目标位置写入 book.sort，保留每本书最新的标题和显隐。交换两个占用中的序号时，在同一事务中先使用合法且未占用的临时序号，再写最终的 1..N，给临时值预留空间并检查列范围。事务提交成功后返回与 book/options 相同格式的整份书单。

取消调序直接还原草稿。书籍不足两本或者草稿没变化时，页面无需发请求。后端收到与当前状态完全一致的合法快照和目标时可直接返回当前书单。创建或他人调序会让旧顺序失效，只编辑书名或显隐仍允许保存书序。

错误响应与页面恢复

失败响应统一为 {code, message, data: {}}。20203 和 20204 是本设计建议分配的书籍业务码，要在两端定义后再联调。以下为建议的调序冲突响应。

建议响应旧书序已失效 
{
  "code": 20203,
  "message": "书单或书序已变化,请刷新后重新调整",
  "data": {}
}
业务码含义或适用操作页面处理
10101 已有字段、书名、显隐或调序数组不合法。显示具体提示，保留待修正内容。
20102 已有所选天体已不存在。清空关联书单，刷新天体选项。
20201 已有旧创建接口发现同一天体的序号被占用。刷新书单核对结果；新表单的排序值为只读。
20202 已有编辑的书籍已不存在。结束该条编辑，刷新当前天体的书单。
20203 建议新增
BOOK_ORDER_CHANGED		完整书单的成员或顺序与调序快照不一致。保留已提交的有效书序，重新读取书单，让管理员基于新顺序调整。
20204 建议新增
BOOK_EDIT_CHANGED		书籍的标题或显隐与编辑快照不一致。保留用户输入供对照，取得最新书籍，重新确认后再保存。
20003 / 20004 已有令牌过期，或令牌缺失、无效。交由已有鉴权拦截器处理。
10201 / 500 已有数据库或服务内部错误。给出失败提示。请求中断、结果未知时先刷新书单核实，尤其要避免重复创建同名书。

将新增业务码放入后端 resp_body 和前端 API_CODE。页面按业务码处理冲突，错误消息供管理员阅读。如果写入已成功而后续刷新失败，应提示「已保存，列表刷新失败」，只重试读取。

联调验收

操作预期结果
选择无书天体，再添加一本隐藏书列表先为空。新书排第 1，隐藏数为 1。
同一天体已有 3 本显示、2 本隐藏的书添加抽屉显示只读的 6。单人提交后末位为 6，并发提交两本时分别为 6 和 7。
给同名书中的一本改标题并隐藏只有选中 ID 的书被修改，所属天体、书序及目录状态保留。取消编辑时不写库。
两名管理员同时编辑一本书第一人保存的修改生效；若第二人的原值已失效，返回 20204，第二人可核对新值后提交。
交换两本书，其中一本隐藏一次请求保存连续序号。重新请求 options 后同样顺序，书名与显隐保留。
调序期间有人新增书籍或保存了不同的顺序旧快照收到 20203，新加入的书和已保存的书序得到保留。另一人仅编辑标题或显隐时调序可以成功。
用重复、漏项或其他天体的 ID 提交按调序节的校验规则返回错误，任何天体的书序都不会被部分写入。

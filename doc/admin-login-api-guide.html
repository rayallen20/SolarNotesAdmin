后端直接使用输入的用户名查询记录，并通过 auth.MatchSHA256() 对输入密码计算摘要后比较。因此前端应原样提交用户名和密码：不用 trim() 改写凭据，也不在前端先算一遍 SHA-256。全空白判断仅用于校验，不修改输入值。生产环境通过 HTTPS 传输登录请求。

2. 区分 HTTP 状态与业务响应码

当前后端对登录成功、参数错误、账号密码错误、限流等已处理结果，均返回 HTTP 200。例如下面这份响应仍代表登录失败：

HTTP 200 · 业务 code 20001点击折叠 / 展开
{
    "code": 20001,
    "message": "账号或密码错误",
    "data": {}
}
业务 code含义页面处理
200登录成功保存令牌与用户名，进入天体管理
10101参数校验或请求体限制错误提示检查登录信息格式
20001用户名不存在或密码不匹配显示“账号或密码错误”
20002密码验证后，凭据记录的条件更新未命中提示重新登录
20005触发登录访问频率限制提示稍后重试，由用户手动再次提交
10201 / 500数据库错误 / 服务内部错误提示服务暂时不可用

以上为文档内的响应示意，不发送登录请求。后端限流统计包括成功登录及到达登录路由的失败请求，OPTIONS 预检不计入；开发代理后的多个浏览器可能共享后端看到的同一 IP 配额，因此不要用循环请求来验收登录。

4. 配置开发环境的 API 地址与代理

当前前端开发配置为 http://localhost:8080，与管理 API 的 4060 端口不一致。这里采用 Vite 开发代理：浏览器向正在访问的前端站点请求 /api，由开发机上的 Vite 转发给同机后端。

浏览器 → VitePOST http://前端主机:5062/api/v1/admin/login
Vite 去除 /api 前缀 → 后端POST http://127.0.0.1:4060/v1/admin/login

这样局域网其他机器也通过前端主机访问接口，代理中的 127.0.0.1 指运行 Vite 的开发机。若后端在另一台机器运行，应把代理 target 改为那台机器的实际地址。

4.2 更新 Vite 配置

4.2.1 定义路径重写函数

先在 vite.config.js 的 import 语句之后、const option 之前加入下面的函数。rewriteApiPath 是在本文件中定义的普通函数，无需额外导入。

vite.config.js · rewriteApiPath() 函数点击折叠 / 展开
/**
 * 去除开发代理路径中的 /api 前缀，保留后端真实的 /v1 路径。
 * @param {string} path 浏览器请求的路径。
 * @returns {string} 转发给后端的路径。
 */
function rewriteApiPath(path) {
    return path.replace(/^\/api/, '')
}

配置中的 rewrite: rewriteApiPath 把这个函数交给 Vite 调用，将 /api/v1/admin/login 转换为 /v1/admin/login。其中 rewrite 是 Vite 的配置项，rewriteApiPath 是这里定义的函数名。

4.2.2 对照完整配置

下面是包含上述函数的完整文件内容，可整体替换 vite.config.js。

5. 新增管理员登录请求模块

loginAdmin(username, password) 接收两个必填参数，内部构造后端要求的 {admin: {username, password}}。函数只在业务成功且响应字段完整时返回管理员对象。

src/api/admin.js点击折叠 / 展开
import request from '@/utils/request'

/**
 * @typedef {Object} LoginRequest 管理员登录接口的请求体。
 * @property {{username: string, password: string}} admin 管理员凭据，按原值提交。
 */

/**
 * @typedef {Object} LoginAdmin 登录接口返回的管理员信息。
 * @property {string} id 管理员 ID，保留字符串形式。
 * @property {string} username 服务端返回的管理员用户名。
 * @property {string} access_token 服务端签发的访问令牌。
 */

/**
 * 检查管理员信息中的 id 字段是否存在且为非空字符串。
 * @param {unknown} admin 待检查的管理员信息。
 * @returns {admin is {id: string}} id 字段通过校验时返回 true。
 */
function hasValidAdminId(admin) {
    if (typeof admin !== 'object' || admin === null) {
        return false
    }

    if (('id' in admin) === false || typeof admin.id !== 'string') {
        return false
    }

    return admin.id !== ''
}

/**
 * 检查管理员信息中的 username 字段是否存在且为非空字符串。
 * @param {unknown} admin 待检查的管理员信息。
 * @returns {admin is {username: string}} username 字段通过校验时返回 true。
 */
function hasValidAdminUsername(admin) {
    if (typeof admin !== 'object' || admin === null) {
        return false
    }

    if (('username' in admin) === false || typeof admin.username !== 'string') {
        return false
    }

    return admin.username !== ''
}

/**
 * 检查管理员信息中的 access_token 字段是否存在且为非空字符串。
 * @param {unknown} admin 待检查的管理员信息。
 * @returns {admin is {access_token: string}} access_token 字段通过校验时返回 true。
 */
function hasValidAdminAccessToken(admin) {
    if (typeof admin !== 'object' || admin === null) {
        return false
    }

    if (('access_token' in admin) === false || typeof admin.access_token !== 'string') {
        return false
    }

    return admin.access_token !== ''
}

/**
 * 请求管理员登录接口，并从解包后的数据中取得管理员信息。
 * @param {string} username 用户输入的用户名。
 * @param {string} password 用户输入的原始密码，不做 trim 或前端哈希。
 * @returns {Promise<LoginAdmin>} 已检查字段类型的管理员信息。
 * @throws {Error} 响应格式异常时拒绝；业务错误和网络错误直接向调用方传递。
 */
async function loginAdmin(username, password) {
    /** @type {LoginRequest} 与后端 LoginReq 对应的请求体。 */
    const body = {
        admin: {
            username,
            password,
        },
    }

    /**
     * request 的响应拦截器已经返回 payload.data。
     * 先作为 unknown 检查，避免误用 AxiosResponse 类型或未经校验的数据。
     * @type {unknown}
     */
    const data = await request.post('/v1/admin/login', body)

    if (typeof data !== 'object' || data === null || ('admin' in data) === false) {
        throw new Error('登录响应格式异常，请稍后重试')
    }

    /** @type {unknown} 待检查的管理员信息。 */
    const admin = data.admin

    if (typeof admin !== 'object' || admin === null) {
        throw new Error('登录响应缺少管理员信息，请稍后重试')
    }

    if (
        hasValidAdminId(admin) === true &&
        hasValidAdminUsername(admin) === true &&
        hasValidAdminAccessToken(admin) === true
    ) {
        return {
            id: admin.id,
            username: admin.username,
            access_token: admin.access_token,
        }
    }

    throw new Error('登录响应中的管理员信息不完整，请稍后重试')
}

export {loginAdmin}

三个字段分别校验

hasValidAdminId()、hasValidAdminUsername() 和 hasValidAdminAccessToken() 各自检查一个字段是否存在、是否为字符串以及是否非空。主函数只组合三个校验结果。

JSDoc 中的 admin is {id: string} 等写法是类型谓词：函数运行时仍返回 true 或 false，同时让 IDE 在校验通过后识别相应字段的类型。

为什么这里取得的是 data.admin？

当前 request.js 的响应拦截器在 payload.code === 200 时返回 payload.data，其他业务码返回被拒绝的 Promise。所以这里 await request.post(...) 的运行时结果是 {admin: {...}}，而不是包含 HTTP 头等信息的 AxiosResponse。

示例先将结果声明为 unknown，检查对象及字段后构造 LoginAdmin。这既对应实际运行时数据，也避免为了 IDE 类型提示再错误地读取一层 response.data。

HTTP 响应：{code, message, data}→拦截器：data→loginAdmin：data.admin→登录页：admin.access_token

6. 实现登录表单与提交过程

用下面完整组件替换登录占位页。点击按钮或在输入框按 Enter，都通过表单的 submit 事件进入 login()。提交锁从校验开始持续到会话保存和路由跳转完成，避免连续点击重复请求。

脚本保持普通函数、完整 JSDoc、显式比较及 template → script → style 的顺序。校验、请求、成功处理使用三个同级的 try...catch，各自处理对应阶段的失败。

src/views/LoginPage.vue点击折叠 / 展开
<template>
    <main class="login-page">
        <el-card class="login-card" shadow="never">
            <template #header>
                <h1>SolarNotes 管理后台登录</h1>
            </template>

            <el-form
                ref="loginFormRef"
                :model="loginForm"
                :rules="loginFormRules"
                :disabled="isSubmitting"
                label-position="top"
                @submit.prevent="login"
            >
                <el-form-item label="用户名" prop="username">
                    <el-input
                        v-model="loginForm.username"
                        name="username"
                        autocomplete="username"
                        placeholder="请输入用户名"
                        clearable
                    ></el-input>
                </el-form-item>

                <el-form-item label="密码" prop="password">
                    <el-input
                        v-model="loginForm.password"
                        name="password"
                        type="password"
                        autocomplete="current-password"
                        placeholder="请输入密码"
                        show-password
                    ></el-input>
                </el-form-item>

                <el-button
                    type="primary"
                    native-type="submit"
                    :loading="isSubmitting"
                    :disabled="isSubmitting"
                    class="login-button"
                >登录</el-button>
            </el-form>
        </el-card>
    </main>
</template>

<script setup>
import {reactive, ref} from 'vue'
import {isNavigationFailure, useRouter} from 'vue-router'
import {ElMessage} from 'element-plus'
import axios from 'axios'
import {loginAdmin} from '@/api/admin'
import useUserStore from '@/stores/user'

defineOptions({
    name: 'LoginPage',
})

/**
 * @typedef {Object} LoginForm 登录表单数据。
 * @property {string} username 用户名，长度为 5～20 个字符。
 * @property {string} password 原始密码，长度为 6～20 个字符。
 */

/** @type {LoginForm} 当前登录表单，凭据按输入原值保存。 */
const loginForm = reactive({
    username: '',
    password: '',
})

/** @type {import('vue').Ref<import('element-plus').FormInstance | null>} 登录表单实例。 */
const loginFormRef = ref(null)

/** @type {import('vue').Ref<boolean>} 是否正在校验、请求登录或处理成功后的跳转。 */
const isSubmitting = ref(false)

/** @type {import('element-plus').FormRules<LoginForm>} 与后端长度及非空白要求对应的规则。 */
const loginFormRules = {
    username: [
        {required: true, whitespace: true, message: '请输入用户名', trigger: 'blur'},
        {min: 5, max: 20, message: '用户名长度为 5～20 个字符', trigger: 'blur'},
    ],
    password: [
        {required: true, whitespace: true, message: '请输入密码', trigger: 'blur'},
        {min: 6, max: 20, message: '密码长度为 6～20 个字符', trigger: 'blur'},
    ],
}

/** 用户 Store 实例，沿用工程中供 IDE 识别的显式类型。 */
const userStore = /** @type {import('@/stores/user').UserStore} */ (useUserStore())

/** @type {import('vue-router').Router} 路由实例。 */
const router = useRouter()

/**
 * 将后端业务错误或普通异常转换为登录提示。
 * @param {unknown} error 后端响应体或其他异常。
 * @returns {string} 可供页面展示的错误说明。
 */
function getBusinessErrorMessage(error) {
    if (typeof error !== 'object' || error === null) {
        return '登录失败，请稍后重试'
    }

    if ('code' in error && typeof error.code === 'number') {
        switch (error.code) {
            case 10101:
                return '登录信息格式不正确，请检查用户名和密码'
            case 20001:
                return '账号或密码错误'
            case 20002:
                return '账号状态已变化，请重新登录'
            case 20005:
                return '请求过于频繁，请稍后再试'
            case 10201:
            case 500:
                return '登录服务暂时不可用，请稍后重试'
        }
    }

    if ('message' in error && typeof error.message === 'string' && error.message.trim() !== '') {
        return error.message
    }

    return '登录失败，请稍后重试'
}

/**
 * 区分业务拒绝、HTTP 错误、超时与未收到响应的连接错误。
 * @param {unknown} error 登录请求抛出的异常。
 * @returns {string} 登录失败提示。
 */
function getLoginErrorMessage(error) {
    if (axios.isAxiosError(error) === true) {
        if (error.code === 'ECONNABORTED' || error.code === 'ETIMEDOUT') {
            return '登录请求超时，请稍后重试'
        }

        if (error.response === undefined) {
            return '暂时无法连接登录服务，请稍后重试'
        }

        if (error.response.status >= 500) {
            return '登录服务暂时不可用，请稍后重试'
        }

        return getBusinessErrorMessage(error.response.data)
    }

    return getBusinessErrorMessage(error)
}

/**
 * 校验并提交登录凭据，成功后保存会话并进入天体管理。
 * @returns {Promise<void>} 本次登录处理结束。
 */
async function login() {
    if (isSubmitting.value === true || loginFormRef.value === null) {
        return
    }

    isSubmitting.value = true

    try {
        /** @type {boolean} 表单校验是否通过。 */
        const isValid = await loginFormRef.value.validate()

        if (isValid === false) {
            isSubmitting.value = false
            return
        }
    } catch {
        // 校验错误由表单项显示，恢复按钮后允许用户修改输入。
        isSubmitting.value = false
        return
    }

    /** @type {import('@/api/admin').LoginAdmin} 成功响应中的管理员信息。 */
    let admin

    try {
        admin = await loginAdmin(loginForm.username, loginForm.password)
    } catch (error) {
        isSubmitting.value = false
        ElMessage.error(getLoginErrorMessage(error))
        return
    }

    try {
        await onLoginSuccess(admin.access_token, admin.username)
        ElMessage.success('登录成功')
    } catch {
        ElMessage.error('登录后的页面未能打开，请刷新页面后重试')
    } finally {
        isSubmitting.value = false
    }
}

/**
 * 清空表单中的密码，保存服务端返回的会话并进入天体管理。
 * @param {string} token 服务端返回的 access_token。
 * @param {string} username 服务端返回的管理员用户名。
 * @returns {Promise<void>} 会话保存及页面跳转完成。
 * @throws {Error} 会话保存或路由跳转失败时抛出。
 */
async function onLoginSuccess(token, username) {
    loginForm.password = ''
    userStore.setSession(token, username)

    /** @type {void | import('vue-router').NavigationFailure} 路由跳转的结果。 */
    const failure = await router.replace({name: 'bodyList'})

    if (isNavigationFailure(failure) === true) {
        throw new Error('未能进入天体管理页面')
    }
}
</script>

实现时保留这些行为

  • 表单校验不通过时，恢复按钮并保留输入；不会向后端发送请求。
  • 不增加旧占位代码中的 @keyup.enter="login" 或按钮 @click="login"，统一由原生 submit 触发。
  • 业务失败由现有响应拦截器拒绝；超时及 HTTP 错误由 Axios 拒绝，页面统一给出相应提示。
  • 后端没有给出限流重试时刻，页面提示用户稍后手动重试，不自动重新发送登录请求。
  • 成功时清空表单密码，保存后端返回的用户名和访问令牌，再跳转 bodyList。
  • 保存会话或跳转失败采用独立提示，避免将这类错误解释为用户名或密码错误。

表单校验 API 参考 Element Plus Form 文档；网络错误与 HTTP 响应错误的区分参考 Axios 错误处理文档。

7. 与现有用户 Store 对接

接口字段与 Store 字段的对应关系如下。已有 setSession() 接收两个字符串参数，直接按顺序传入即可。

服务端字段前端用途
admin.access_token传入 setSession() 第一个参数，保存为 userStore.token
admin.username传入第二个参数，保存为 userStore.username，供顶部用户栏显示
admin.id在 LoginAdmin 类型中保留为字符串；当前登录后的页面尚不需要持久化该字段

当前 Store 会写入 solar-notes-admin-token 和 solar-notes-admin-username 两个本地存储键，刷新后恢复。密码只存在于表单中，不增加密码持久化逻辑；浏览器自己的密码管理器可通过 autocomplete 属性识别登录表单。

现有 request.js 会在有 token 时附加 Authorization: Bearer …。登录接口本身只验证请求体中的用户名和密码，后续受保护接口的令牌校验需由后端相应中间件执行。

8. 为后台页面补上前端路由守卫

在 /admin 父路由上设置 meta.requiresAuth，它的三个子页面都经过同一检查。守卫在组件外读取 Store，显式使用现有的 pinia 实例。

src/router/index.js点击折叠 / 展开
import {createRouter, createWebHistory} from 'vue-router'
import pinia from '@/stores'
import useUserStore from '@/stores/user'

/** @type {import('vue-router').RouteRecordRaw[]} 路由列表。 */
const routes = [
    {
        path: '/',
        redirect: '/admin',
    },
    {
        path: '/login',
        name: 'login',
        component: () => import('@/views/LoginPage.vue'),
    },
    {
        path: '/admin',
        component: () => import('@/views/LayoutPage.vue'),
        redirect: {name: 'bodyList'},
        meta: {
            requiresAuth: true,
        },
        children: [
            {
                path: 'bodies',
                name: 'bodyList',
                component: () => import('@/views/BodyListPage.vue'),
                meta: {
                    title: '天体管理',
                    description: '管理太阳与八大行星的简介信息',
                },
            },
            {
                path: 'users',
                name: 'userList',
                component: () => import('@/views/PlaceholderPage.vue'),
                meta: {
                    title: '用户管理',
                    description: '查看与管理用户信息',
                },
            },
            {
                path: 'notes',
                name: 'noteList',
                component: () => import('@/views/PlaceholderPage.vue'),
                meta: {
                    title: '笔记管理',
                    description: '查看和管理笔记内容',
                },
            },
        ],
    },
]

/** @type {import('vue-router').RouterOptions} 路由配置。 */
const option = {
    routes,
    history: createWebHistory(import.meta.env.BASE_URL),
}

/** @type {import('vue-router').Router} 路由实例。 */
const router = createRouter(option)

/**
 * 访问后台页面前检查本地是否有令牌。
 * @param {import('vue-router').RouteLocationNormalized} to 即将进入的路由。
 * @returns {true | import('vue-router').RouteLocationRaw} 允许继续或返回登录页地址。
 */
function checkLogin(to) {
    /** 当前 Pinia 实例中的用户 Store，在组件外显式传入 pinia。 */
    const userStore = /** @type {import('@/stores/user').UserStore} */ (useUserStore(pinia))

    if (to.meta.requiresAuth === true && userStore.token === '') {
        return {
            name: 'login',
            replace: true,
        }
    }

    return true
}

router.beforeEach(checkLogin)

export default router

访问根路径时先进入 /admin：本地没有 token 就返回登录页；有 token 则显示天体管理。/login 始终可手动打开，便于本地残留旧令牌时重新登录。父子路由的 meta 合并行为可对照 Vue Router 路由元信息文档。

这个守卫检查的是“本地是否存在令牌”。令牌是否有效、是否过期、是否被撤销，需要后端受保护接口验证。当前后端虽已提供 JWT 签发与解析函数、20003/20004 业务码，但 main.go 尚未注册受保护的业务路由或令牌校验中间件，因此本次示例没有声称已经完成服务端登录态校验。

现有布局的退出操作调用 clearSession() 后跳转登录页，可继续配合此守卫使用。后端当前没有注册退出或刷新令牌接口，因此这里的退出是清除当前浏览器会话；后续增加服务端撤销能力时再接入对应 API。

现象应检查的内容
仍请求 localhost:8080开发环境变量是否改为 /api，是否存在覆盖该值的本地环境文件，Vite 是否已重启

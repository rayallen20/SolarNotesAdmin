2. 为什么页面正常，菜单却没有选中

当前路由配置没有开启 strict: true。默认情况下，Vue Router 允许结尾斜杠，因此 /admin/users 和 /admin/users/ 都会匹配用户管理页面。

但是，Element Plus 菜单使用激活值匹配菜单项的 index。当前模板直接传入 route.path，它会保留访问地址中的结尾斜杠；菜单项则通过路由名称生成配置中的路径，两者可能不同。

这个问题也存在于早先的布局参考文档中。修复时应让当前高亮路径和菜单项路径都由路由名称解析，使用配置中的同一个路径。

依据：Vue Router 的 sensitive 与 strict 选项、Element Plus 的 default-active 与 router 属性。

3. 修改绑定并新增计算属性

第一步：替换模板中的高亮绑定

在 src/views/LayoutPage.vue 的 el-menu 上，将：

修改前 · template 中的这一行
:default-active="route.path"

替换为：

修改后 · template 中的这一行
:default-active="activeMenuPath"

第二步：在 script setup 中新增以下代码

将下面代码放在已有 const router = useRouter() 之后。当前文件已经导入 computed、定义 route 和 getMenuPath()，继续复用这些内容，无须重复添加它们。

src/views/LayoutPage.vue · script setup 中新增
/**
 * 当前选中菜单的规范路径，与菜单项 index 使用相同的解析规则。
 * @type {import('vue').ComputedRef<string>}
 */
const activeMenuPath = computed(getActiveMenuPath)

/**
 * 根据当前路由名称计算应高亮的菜单路径。
 * @returns {string} 当前路由的规范路径；没有字符串路由名称时返回空字符串。
 */
function getActiveMenuPath() {
    if (typeof route.name === 'string') {
        return getMenuPath(route.name)
    }

    return ''
}

computed 会根据当前路由重新计算高亮值；模板会自动解包计算属性，直接使用 activeMenuPath，不需要写 activeMenuPath.value。

只有当前路由名称是字符串时才调用已有函数；否则返回空字符串，表示没有要选中的菜单，避免在当前路由没有名称时继续解析地址。

核对已有 getMenuPath()，无需再定义一次

LayoutPage.vue 中已有的函数 · 保留
/**
 * 根据路由名称获取菜单对应的完整路径。
 * @param {string} routeName 路由配置中唯一的名称。
 * @returns {string} 根据当前路由配置解析出的完整路径。
 * @throws {Error} 路由名称不存在或缺少必填路径参数时抛出。
 */
function getMenuPath(routeName) {
    return router.resolve({name: routeName}).path
}

router.resolve() 只解析目标路径，不执行跳转。因此访问 /admin/users/ 时，地址栏可以继续保留结尾斜杠，菜单也能正常选中。

4. 对照修改后的菜单片段

下方只列出菜单部分。三个菜单项继续调用原来的 getMenuPath()，本次需要替换的模板绑定只有 default-active。

src/views/LayoutPage.vue · 菜单片段
<el-menu
    router
    :default-active="activeMenuPath"
    background-color="#2D3A4B"
    text-color="#AEB8C7"
    active-text-color="#FFFFFF"
    class="sidebar-menu"
>
    <el-menu-item
        :index="getMenuPath('dashboard')"
        title="工作台"
        aria-label="工作台"
    >
        <el-icon><HomeFilled></HomeFilled></el-icon>
        <span>工作台</span>
    </el-menu-item>

    <el-menu-item
        :index="getMenuPath('userList')"
        title="用户管理"
        aria-label="用户管理"
    >
        <el-icon><User></User></el-icon>
        <span>用户管理</span>
    </el-menu-item>

    <el-menu-item
        :index="getMenuPath('noteList')"
        title="笔记管理"
        aria-label="笔记管理"
    >
        <el-icon><Document></Document></el-icon>
        <span>笔记管理</span>
    </el-menu-item>
</el-menu>

页面标题、用户名、退出逻辑以及样式无需因这次高亮修复而修改；路由名称仍使用 dashboard、userList、noteList。

查询参数和 hash 不属于 route.path；此处包含它们的地址用于确认修复不会影响带参数链接的高亮。

6. 适用范围

本修复适用于当前三个菜单与三个字符串命名的静态路由一一对应的结构，并保留了“修改 path 后无须同步修改菜单字符串”的用法。

如果后续新增用户详情等页面，并希望详情页也高亮“用户管理”，需要另行约定详情页所属的菜单；仅把详情路由名称解析成详情路径，并不会自动选中列表菜单。

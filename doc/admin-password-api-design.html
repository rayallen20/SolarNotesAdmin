打开修改密码原型

修改密码 API 对接定义

供「账号管理 → 修改密码」前后端对接使用。已确定的交互是改密成功后回到登录页，由管理员使用新密码重新登录。

1. 接口与鉴权

建议新增　POST /v1/admin/password/change

当前后端已提供 POST /v1/admin/login。本次建议新增一个修改当前管理员密码的路由，挂在已有管理端鉴权中间件下。管理员身份取自经 Bearer 鉴权的 middleware.CurrentAdminID(c)。重新登录仍调用现有登录接口。

HTTP请求行和请求头
POST /v1/admin/password/change HTTP/1.1
Authorization: Bearer <access_token>
Content-Type: application/json

上面的路径是后端路由。使用现有 Vite 开发代理时，浏览器 Network 中可见 /api/v1/admin/password/change。后端路由注册 · 鉴权上下文

2. 请求体与表单映射

沿用登录接口的 admin 对象包装。点击「确认修改」时，前端先逐字比较两次新密码。一致后提交原密码和新密码。请求体无需账号 ID、用户名或确认密码字段。

JSON修改当前管理员密码
{
  "admin": {
    "current_password": "SolarDemo1",
    "new_password": "OrbitDemo2026"
  }
}
来源请求字段类型与服务端规则
原密码admin.current_password必填字符串，至少包含一个非空白字符。用输入原值核验当前管理员保存的密码。
新密码admin.new_password必填字符串，长度为 6–20 个 Unicode 码点，至少包含一个非空白字符。沿用管理端登录的长度和非空白要求。前端按 Unicode 码点计数。
确认新密码仅用于表单校验必填，按原始字符串与新密码完全相等。两次输入不一致时在确认字段提示，前端不发请求。

admin 必须是对象。请求结构错误、字段缺失、null、类型错误或新密码长度越界时，返回 10101。空白检测只用于校验，密码中的大小写、首尾空格和 Unicode 字符原样参与核验及保存。上面的请求只使用演示值。部署时通过 HTTPS 传输密码和 Bearer 令牌，业务日志和错误响应均不回显这些值。

按已评审的原型，本提案允许新旧密码相同。原密码核验通过后仍执行会话撤销和重新登录。

3. 响应体与页面行为

沿用项目约定，控制器通过 HTTP 200 返回业务结果，前端依据数值型 code 分支处理。message 是字符串。本接口成功与失败时 data 均为空对象 {}。下列示例是浏览器收到的完整 JSON。

成功后回到登录页

JSON密码与会话变更均已提交
{
  "code": 200,
  "message": "success",
  "data": {}
}

服务端返回 JSON。跳转由前端完成。收到业务成功后，前端清空三个密码输入框，调用 userStore.clearSession() 和 router.replace({name: 'login'})，在登录页提示「密码已修改，请使用新密码重新登录」。现有 Axios 拦截器已将成功响应解包为 data。新令牌由管理员下一次成功登录时签发。公共请求处理 · 登录态清理

失败时区分原密码错误和登录态失效

JSON原密码不正确 · 建议新增业务码
{
  "code": 20006,
  "message": "原密码不正确",
  "data": {}
}
JSON已撤销的旧令牌再次访问受保护接口
{
  "code": 20004,
  "message": "登录状态无效,请重新登录",
  "data": {}
}
业务码含义及归属前端行为
20006建议新增。当前令牌有效，原密码核验不通过。后端常量建议命名为 CurrentPasswordIncorrectCode。保留登录态和表单，在原密码字段提示并允许修正。
10101复用。请求参数校验失败。停留在表单，提示检查输入。
20003 / 20004复用。令牌过期 / 缺失、无效、已撤销，或写入前当前会话已被替换。交给公共鉴权处理返回登录页。只有接到本次改密成功响应时才显示改密成功提示。
10201 / 500复用。数据库操作失败 / 服务内部错误。提示操作失败，避免回显密码或技术细节。

已有的 20001 表示登录时账号或密码错误。改密使用独立的 20006，前端可直接定位原密码字段。请求超时或连接中断时，提交结果未知。提示使用新密码登录核实，避免自动重发写请求。现有业务码 · 前端鉴权错误分类

4. 写入与会话撤销

后端为每个管理员保存 password_hash 和当前有效的 token_hash。鉴权流程会检查 JWT 并比对库中的令牌摘要。清空 token_hash 后，持有同一旧令牌的其他标签页或设备，下次访问受保护接口时也会收到鉴权错误。

  1. 锁定并核对当前会话。 通过鉴权和参数校验后，在事务中按管理员 ID 读取并锁住对应记录。写入前比对本次请求所用 Bearer 令牌的摘要与行内当前 token_hash。记录消失、令牌已被撤销或并发登录已替换令牌时，返回 20004。
  2. 核验原密码。 按当前登录实现兼容的方式，将 current_password 的原值与该行的 password_hash 核对。原密码不匹配时返回 20006，保留密码和会话。
  3. 一起更新两个字段。 显式写入新密码的哈希，并将 token_hash 设为空字符串。使用 GORM 时确保空字符串参与 UPDATE。提交成功后返回 200。写入失败回滚。现有登录写令牌时会按所读取的密码摘要做条件更新，需保留这个条件，防止已验证旧密码的在途登录覆盖撤销结果。

当前中间件在上下文中提供管理员 ID。实现改密时可同时传递本次已验证令牌的摘要供事务内比对，确保对应的是发起请求的会话。鉴权中间件 · 登录与会话核验 · 管理员模型与登录条件更新

5. 联调验收

使用测试管理员和一组不同的新旧密码。先登录取得令牌 A，再通过下列操作核对结果。

操作预期结果
令牌 A 有效，提交正确原密码和合规新密码。返回 200 和 data: {}。页面提示改密成功并回到登录页。用旧密码登录返回 20001，用新密码登录成功并取得新令牌。
保留令牌 A，改密成功后用 A 请求 GET /v1/planet/list。在 A 的有效期内也会返回 20004。用新登录取得的令牌访问同一接口成功。
有效会话提交错误原密码。返回 20006。页面停留在原密码字段，原登录令牌仍可使用。
两次新密码不一致。或直接发送长度为 5、21 的新密码。确认不一致时 Network 没有改密请求。直接发送越界值返回 10101。6 和 20 个码点均是合法长度，首尾空格按原值计数。
在会话有效期内，用两个标签页的同一令牌同时提交不同的新密码。只有一次成功，另一次返回 20004。最终只可用成功提交的新密码登录。
在测试环境模拟数据库写入失败。返回 10201，修改未提交时原密码和原令牌仍可用。

交付给后端的新增项为一条受保护路由、一种原密码错误业务码，以及一次同时更新密码和撤销会话的写操作。现有登录接口的请求体和响应体可继续复用。

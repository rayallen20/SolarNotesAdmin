用图看懂 vh 与 dvh

地址栏展开时，网页到底有多高？把“元素的高度”和“当前可见区域”画在一起，就能看到两种单位的区别。

两个计算基准 切换图示 对照数值 回到后台布局

1. 先分清两个计算基准

视口指浏览器用来显示网页的区域。1vh 和 1dvh 都取相应高度的 1%，但参照的高度不同：

vh：以大视口为基准

按可伸缩的浏览器界面收起时的视口高度计算。在当前标准中，vh 与 lvh 等价。

dvh：以动态视口为基准

根据地址栏等浏览器界面的展开、收起状态调整。100dvh 可以跟随当前动态视口的高度变化。

依据：W3C：大视口、小视口和动态视口、MDN：视口相对长度单位。

2. 点击切换，观察页面底部的位置

假设地址栏收起后的视口高 800px；展开时，地址栏和工具栏合计占去 100px，当前可见网页区域剩下 700px。本例只切换工具栏状态，保持窗口大小和设备方向不变。

先看左图：页面本身仍有 800px 高，当前只能看到其中的 700px。再看右图：页面缩短为 700px，底部按钮跟着上移。点击“地址栏收起”，两边都会显示为 800px。

3. 把两种状态放在一起对照

地址栏状态可见网页高度100vh100dvh
展开，占去 100px700px800px700px
收起800px800px800px

vh 并非永远不变。调整窗口高度或旋转设备时，它也可能改变。本例中的 100vh 保持 800px，是因为只改变工具栏状态，大视口本身没有改变。

桌面浏览器通常没有这种伸缩工具栏带来的高度差，所以 100vh 与 100dvh 通常表现相同。

图示只解释地址栏等伸缩界面；软键盘的行为需另行考虑。示意图中的平滑过渡用于展示两个状态，真实浏览器在工具栏动画期间不一定逐帧更新 dvh。依据：W3C 动态视口定义。

4. 回到 LayoutPage.vue 的写法

后台公共布局需要占满当前视口高度，因此优先使用 100dvh。前面保留 100vh，供不认识 dvh 的浏览器使用：

LayoutPage.vue · style 部分（标准 CSS 注释，也可用于 SCSS）
.layout-page {
    height: 100vh;  /* 兼容不支持 dvh 的浏览器 */
    height: 100dvh; /* 支持时覆盖上一行，使用动态视口高度 */
    overflow: hidden;
}
  • 支持 dvh：后面的有效声明覆盖前面的声明，最终使用 100dvh。
  • 不支持 dvh：忽略第二行，最终使用 100vh。

这两行高度不会相加。当前布局示例中，外层的 overflow: hidden 配合内容区的 overflow: auto 使用，让右下内容区独立滚动。

相关代码见：后台布局参考文档 · LayoutPage.vue。
